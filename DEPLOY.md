# Deploying Luckiest AI to Render

Step-by-step. Should take ~10 minutes.

## What gets deployed

A single Node.js web service running on Render's `starter` plan ($7/mo) with a
1 GB persistent disk ($0.25/mo) mounted at `/var/data`. The SQLite database and
uploaded images live on that disk, so they survive deploys and restarts.

**Want it cheaper?** Change `plan: starter` → `plan: free` in `render.yaml` and
delete the `disk:` block. The app will run, but the database is wiped on every
restart — fine for a demo, not for production.

---

## Step 1 — Push to GitHub

Render deploys from a Git repo. From PowerShell in `C:\Users\ifean\Desktop\luckiest-ai`:

```powershell
git init
git add .
git commit -m "initial commit"
```

Then create an empty repo at https://github.com/new (don't add a README), and:

```powershell
git remote add origin https://github.com/YOUR_USERNAME/luckiest-ai.git
git branch -M main
git push -u origin main
```

> Sanity check: `.gitignore` already excludes `.env`, `node_modules/`, `data/*.db`,
> and `uploads/*` — your local secrets and database won't be pushed.

## Step 2 — Create the Blueprint on Render

1. Go to https://dashboard.render.com → **New +** → **Blueprint**.
2. Click **Connect a repository** and authorize GitHub if you haven't already.
3. Pick the `luckiest-ai` repo you just pushed.
4. Render detects `render.yaml` and shows a preview. Click **Apply**.
5. It will create the web service, attach the persistent disk, and ask you to
   fill in any env vars marked `sync: false`. You **must** provide values for:

   | Env var | What to set it to |
   |---|---|
   | `ADMIN_PASSWORD` | A strong password for the admin login |
   | `ANTHROPIC_API_KEY` | Your `sk-ant-...` key from console.anthropic.com |

   The following are optional — leave blank if you're not using that integration:
   - `META_APP_ID`, `META_APP_SECRET`
   - `WHATSAPP_PHONE_NUMBER_ID`, `WHATSAPP_TOKEN`
   - `OPENAI_API_KEY` (for voice transcription)

   The following are auto-generated by Render, leave them alone:
   - `SESSION_SECRET`, `META_VERIFY_TOKEN`, `WHATSAPP_VERIFY_TOKEN`

6. Click **Apply**. Render starts the first build — takes ~3 minutes
   (npm install needs to compile `better-sqlite3` natively).

## Step 3 — Note your public URL

Once the build is green:

- Render assigns a URL like `https://luckiest-ai-xxxx.onrender.com`. You'll see
  it at the top of the service page.
- The app exposes itself there via `RENDER_EXTERNAL_URL` automatically — you
  don't need to set `PUBLIC_URL` manually.
- Test it: open `https://luckiest-ai-xxxx.onrender.com/login.html` and sign in
  with `admin@luckiest.ai` + the password you set in step 2.

## Step 4 — Wire up your platforms

Once the service is live, the webhook URLs to register in each platform are:

| Platform | URL | Verify token |
|---|---|---|
| Facebook (Page) | `https://YOUR-URL.onrender.com/webhooks/meta` | `META_VERIFY_TOKEN` value from Render env |
| Instagram | (same URL — Meta uses one endpoint for both) | (same) |
| WhatsApp Cloud API | `https://YOUR-URL.onrender.com/webhooks/whatsapp` | `WHATSAPP_VERIFY_TOKEN` value from Render env |
| Telegram | (no webhook — bots poll automatically) | — |

To find the auto-generated verify tokens: Render dashboard → your service →
**Environment** → click each of `META_VERIFY_TOKEN` and `WHATSAPP_VERIFY_TOKEN`
to reveal.

In the app itself, paste your platform tokens (Page access token, WhatsApp
permanent token, BotFather bot token) on the **/platforms.html** page after
logging in.

## Step 5 — Verify it's working

- **Health check:** `GET https://YOUR-URL.onrender.com/healthz` should return
  `{"ok":true,"ts":...}`.
- **Logs:** Render dashboard → your service → **Logs** tab.
- **Disk usage:** Render dashboard → your service → **Disks** tab.

## Updating later

Any `git push` to `main` triggers an auto-deploy. To pause that, switch
`autoDeploy: true` → `false` in `render.yaml`.

## Cost summary

| Item | Monthly |
|---|---|
| Starter web service | $7.00 |
| 1 GB persistent disk | $0.25 |
| **Total** | **~$7.25/mo** |

Plus your Anthropic API usage, which is metered per token used.

## Switching to free tier

```yaml
# in render.yaml
plan: free
# delete the disk: block at the bottom
```

Caveats of free tier:
- No persistent storage — SQLite db resets on every deploy/restart
- Spins down after 15 minutes of inactivity (first request after that takes ~30s)
- Single instance only

For real production traffic, scale up to `standard` ($25/mo) and consider
swapping SQLite for Render Postgres.
